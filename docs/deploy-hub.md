## 二、为什么不做成菜单（记下理由，免得以后又有人加回去）

1. **菜单是「站级导航」，栏目是「页级分区」** —— 三个子项是同一天象内容的三条切面
   （今日 / 未来 / 历史），彼此并列、常来回切；做成三个菜单项会把导航栏撑长，
   而且每一项点进去都只看到三分之一的内容。
2. **菜单项会各自成为独立 URL**，于是「今日天象」页与「未来预告」页会
   在搜索结果里**互相竞争**同一个主题词。合成一页三栏目后，
   全部内容在同一 URL 下，权重集中。
3. **页内切换不产生额外请求**，三个栏目一次加载完（内容全在 DOM 里，见下）。

## 三、三种装配方式（按需选，默认第一种）

### 方式 A｜页内三栏目 + 切换条（**推荐**，默认）

```
[astro_hub]
```

三栏目标头横排，点一下切换内容区。切换**纯 CSS**（`radio` + `label`），
**零脚本** —— 这一点是硬约束，理由见第五节。

### 方式 B｜三栏目纵向平铺

```
[astro_hub tabs="0"]
```

三条内容依次铺开，不分页。适合「一次性看完」的场景，SEO 上三个分区同时可见。

### 方式 C｜只保留部分栏目

```
[astro_hub today="0" future="1" past="0"]     只留「未来天象预告」
[astro_hub today="1" future="0" past="0"]     只留「今日天象」
[astro_hub today="0" future="0" past="1"]     只留「历史上今日天象」
```

### 参数总表

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `tabs` | `1` / `0` | `1` | 1＝页内切换；0＝纵向平铺 |
| `today` | `1` / `0` | `1` | 是否显示「今日天象」栏目 |
| `place` | `auto` / `off` / 城市键 | `auto` | 透传给 `[astro_today]`：`auto` 按访问地就近、`off` 关闭选择器、`beijing` 固定北京 |
| `future` | `1` / `0` | `1` | 是否显示「未来天象预告」栏目 |
| `period` | `month` / `quarter` / `year` / `next12` | `month` | 透传给 `[astro_forecast_report]` |
| `past` | `1` / `0` | `1` | 是否显示「历史上今日天象」栏目 |

**若不想用栏目外壳**，三个子短代码也可以单独放（例如各自做成独立页面）：

```
[astro_today place="auto"]
[astro_forecast_report period="month"]
[astro_history_today]
```

## 四、三个栏目各自是什么

| # | 栏目 | 内容 | 数据来自 |
|---|---|---|---|
| 1 | **今日天象** | 当日天体位置 ＋ 观测地相关量（日出日落、昼长、三种晨昏、月出月落）；**观测地可选**，默认按访问地就近 | `wp_astro_daily`（地心量）＋ `wp_astro_daily_site`（观测地量） |
| 2 | **未来天象预告** | 月 / 季 / 年度汇总表，可下载 MD、CSV，可打印成 PDF | `wp_astro_events`（`side=future`） |
| 3 | **历史上今日天象** | 历史同日的天象记录（史载 ＋ 自算）；明确区分「**未录入**」与「**确实没有**」 | `wp_astro_events`（`side=past`） |

## 五、两条硬约束（改动前必读）

### 5.1 栏目切换**必须**是纯 CSS，不得改成 JS

平台（WordPress.com）会对正文跑两道路后处理：

1. `wpautop` —— 把空行换成 `</p><p>`，**内联脚本里的空行会被拆断**；
2. 某些窗口内的**裸与号被替换成实体引用**，而 `<script>` 内容**不做实体解码**
   ⇒ 逻辑与会变成两个实体串 ⇒ **JS 语法错、整块脚本失效**。

⇒ 内联脚本随时可能整块失效（v1.3.0「老黄历线上失效」的真因就是这个）。
栏目外壳因此**一个脚本都不用**：切换状态存在 `radio` 的 `:checked` 上，由 CSS 读。

> `verify_package.py` 里有一条判据盯着这件事：
> 「栏目外壳**不含脚本标签**」—— 谁改成 JS，收工闸门当场报红。

### 5.2 打印时三栏**全部展开**

`astro-style.css` 的 `@media print` 段强制 `.kcj-astro-hub-pane { display: block !important }`。
否则用浏览器打印（或「另存为 PDF」）时，**只有当前那一栏会被印出来**，
而「报告少了两栏」这种错，不下功夫根本发现不了。

## 九、v2.1.0 增量：历史栏目扩族（装配方式不变）

**为什么改**：只收月食时，288 条摊到 366 个「月-日」上**只覆盖 133 天**，
**其余 232 天打开页面是空的**（36.3%）。逐族量过年率与覆盖后决定扩到三族：

| 族 | 年率（12 年样本） | 覆盖月-日（12 年样本） |
|---|---|---|
| 月食 | 2.29 | 133 |
| **流星雨** | **15.00** | 38 |
| **行星天象** | **19.66** | 194 |
| 日食 | 0（**不生成**） | 0 |

> ★ **全量实测结果（2026-09-23 跑完，126 年 1900—2025）**：
> 共 **4,672 条**（月食 **288** ／ 流星雨 **1,890** ／ 行星天象 **2,494**）、用时 **1,831 s（≈30.5 分钟）**、
> 产物 sha1 **`0fc2acdb01ec`**（`data/events_past.json`，8,158,089 B）——★ **口径**：脚本自报的是 **JSON 正文**的 sha1（**不含末尾换行**）；**整档文件** sha1 ＝ `f6686d52ab69`（8,158,089 B）。
> 实测年率：月食 **2.29** ／ 流星雨 **15.00** ／ 行星 **19.79**（12 年样本值 19.66，吻合）。
> **「月-日」并集覆盖 ＝ 366 / 366 ＝ 100%** —— 只收月食时为 **133 / 366 ＝ 36.3%**，
> 即**扩族把「一年里六成四的日子打开是空的」变成「一天都不空」**。

**页面侧配套**（不加这两样，扩族反而把页面弄坏）：

* **同名天象成组渲染** —— 组名＝标题去掉末尾的「日期形括号」（正则只匹配 `（YYYY-MM-DD）`，
  **不能一刀切剥任意括号** —— 否则「土星留（转逆行）」与「土星留（转顺行）」这两种**相反**的天象会被并成一组）。
  组内 ≥6 条即折成「年份清单」＋ 最近一次明细；＜6 条仍逐条（月食一天最多 4 条 ⇒ 明细不丢）。
* **「前后几天」跳转**（`?kcj_md=MM-DD`）—— 基准年取 **2028**（闰年）。
  用非闰年算「`02-28` 加一天」会跳到 `03-01`，`02-29` 永远不可达。

★ **默认族的 `solar_eclipse` 不要删**：它一条都没收录，但正因为它在默认族里，
页面才会打出「该族未录入 ⇒ 不能据此说这一天没有」这句如实说明。删了它，这句也就没了。

**重传要求**：改了插件文件（短代码／模板／CSS）⇒ **必须重传一次 zip**；
`KCJ_ASTRO_SCHEMA` 仍为 **3**（表结构未变）⇒ **无需重新激活**。
