## 六、回滚机制

- **数据层**：`wp_astro_daily` 按 `uk_jd` / `uk_date_str` upsert，重算不产生重复行；`data_version` 标识算法/星历/ΔT 版本，便于识别哪些行需重算。
- **快照**：每次构建保留 `--json` 导出；异常时按快照重导（REST 分批 upsert 幂等）。
- **页面/CDN**：导入成功自动清 transient；`POST /flush-cache` 手动兜底。
- **插件**：停用不删表；彻底卸载需手工 `DROP`（语句见 `docs/deploy.md` §10.2）。
- **URL**：旧前缀 `/sky/forecast/` → `/sky-forecast/` 走 301，不产生死链。

## 七、风险与缓解

| 风险 | 缓解 |
|---|---|
| **星历覆盖不足**（de421 仅 1899-07-28—2053-10-08） | 内置区间表 + 运行时守卫；覆盖外自动降级 Meeus 解析式并如实标注；若确需全程星历，另行评估 DE431 / DE422 |
| **算力**（5000 年日粒度不可行） | 承诺档 1900—2050（≈5.5 万天，4 进程约 1 h）+ 覆盖外事件级 |
| **jd 尺度混用**（F17，UT 当 TT） | 新增显式 UT↔TT 换算，输出 `jd_ut` 与 `jd_scale`；曾导入的 1900 前 / 2053 后数据需重导 |
| **CPT 注册时机错**（F20，必崩） | 注册挂 `init`（每请求），激活钩子只建表 + 排程 + flush |
| **主题目录不可写**（F21） | 插件内置模板 + `template_include` 注入；主题同名模板优先 |
| **WP.com 不开放外部 DB** | 改走插件 REST 导入（应用程序密码鉴权 + 白名单 + 分批） |
| **托管环境拒绝程序建表** | 回退：手动执行 `sql/install_tables.sql` |
| **本机无 PHP runtime** | tree-sitter 真语法解析 + 符号定义↔引用核对（不等于解释器）；**线上首次激活需人工盯一次 500** |
| **幂等性** | 三处漏洞已修：`uk_date_str`、`uk_from_to_rel`、改判 REST 导入返回值 |
| **合规**（占星类红线） | 已删除择日类字段；可见性只描述观测条件；紫金山历表仅内部比对；ICP / `llms.txt` / 法务审阅由用户侧闭环 |
