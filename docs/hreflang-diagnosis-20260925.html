先说结论，三点。
  1. 你的判断方向对，但实况比「完全没做」更复杂：站点不是没有 hreflang，而是「做了、分三层、缺一层」。 语言子页（16 个）已经完整合规，父栏目页也合规 —— 这是插件 v2.3.7/v2.3.8 早前做过的手艺。
  2. 真正的缺口在文章页（post）：一条都不出。你举的《立春换岁》正是这一类，确实零互指。 根因是 includes/hreflang.php 第 81 行一句 if (!is_page()) return $empty; —— 文章是 post，is_page() 恒为 false，整条支路被挡死。
  3. 不需要装多语言插件，也不必改 Rank Math。插件里那套「按父子关系＋slug 配对」的现成机制， 只要把它从 page 扩到 post 即可 —— 且文章侧已有比 slug 更权威的配对锚：WordPress 分类「中文版」(63494103) / 「英文版」(63494104)， 22 篇 post 已全部正确归类。

一、hreflang 到底是干什么的（一句话）

它是给搜索引擎的「这两页是同一篇内容的两个语言版本」声明书，不是翻译插件、不影响页面显示。 写了，Google 会把中英两版合并成一个成果条目、把权重并到一处、按读者语言择优展示； 不写，Google 视作两篇独立网页 —— 学术产出上就会被当成重复内容，这正是你担心的权重分散。

★ 它是双向契约。A 页声明 B 是它的英文版，B 也必须声明 A 是它的中文版；缺一侧则整组作废。 这一条是本方案所有设计的出发点。

缺口根因（源码逐行核到）

// includes/hreflang.php:81  —— 一句挡死了全部文章页
if (!function_exists('is_page') || !is_page()) {
    return $empty;      // ← 文章是 post，is_page() 恒 false，直接返回空
}

文件头 L24–34 把「三类页面」写成「语言子页 / 父栏目页 / 其余页（首页、文章、CPT、归档）」—— 文章被归进「其余页」只出 x-default，而 is_page() 这道闸连 x-default 都没让它出去。 ⇒ 设计与实现对不上，是这次缺口的直接来源。

首页那三条为什么判「作废」

首页出了 en → /en/，但 /en/ 页面侧一条 hreflang 都没有（实测 0 条）。 双向契约缺一侧 ⇒ Google 整组忽略。且首页那三条的属性顺序与插件输出不同（rel→href→hreflang vs 插件 rel→hreflang→href） ⇒ 确认来自另一层（主题或 Rank Math），非本插件。这一层需要单独定位后再处置。

四、解决办法：三层，按代价从小到大

  1. 主力方案（推荐 · 改一个支路即可）
    在 includes/hreflang.php 里把 article 支路补上，判据改用分类锚而非 slug： 
    // 文章页配对（新增）—— 不靠写死 ID，靠「同分类体系内的互译标记」
· 命中 post ⇒ 读它的 categories
· 含 63494104(英文版) ⇒ 本页为 EN，去找它在中文版的对手
· 含 63494103(中文版) ⇒ 本页为 ZH，去找它在英文版的对手
· 配对锚落库 ⇒ 输出 zh-CN / en / x-default 三条（x-default 依旧指中文）
· 配对不齐 ⇒ 只出 x-default 指自身（沿用现成的「宁缺勿造」纪律）
    关键问题：怎么知道 190 对应的是 10？三种可选锚，按可靠性排序：
    锚做法评价
    A. 互译 ID 元字段 给每篇 post 加一个 translation_of 自定义字段，存对手 post id 最稳 双向、显式、改版不失效；需一次性回填 5 对
    B. slug 约定 约定同篇中英 slug 前缀一致 不合适 现状中英 slug 完全不同（中文是 URL 编码），无法靠前缀配
    C. 标题/正文相似度猜 自动比对 不用 违背本项目「不猜」纪律；会把《立春换岁》那类错配当互译
    ⇒ 建议取 A：加一个元字段，5 对回填一次，之后每篇新英文稿发布时同步填。
    若你希望零改后台，退一步可用「篇号 ＋ 语言分类」组合做锚（英文版分类内的 post 找同篇号中文 post）， 但本地篇号现有错配，须先把命名理干净 —— 不如 A 直接。
  2. 顺带修首页那三条（小）
    先定位那层是谁输出的（主题 or Rank Math）；两种走法—— ① 让它对 /en/ 也输出对等三条（补全双向）； ② 或把首页从该层排除，改由插件统一输出（口径一致）。建议 ②：一处输出、一处口径、便于核对。
  3. 不要做的事（避免引入新病）
    • 不装多语言插件（Polylang/WPML）：站点不是多语言架构，装了要重排全站 URL，代价远超收益。
    • 不改 Rank Math：免费版无 hreflang filter，动它没有着力点。
    • 不写 canonical/robots：那是 SEO 插件的面，越界会打架（插件本身也已守此边界）。
    • 不靠猜配对：宁可只出 x-default，也不给错关系 —— 错配对比不配对更伤。
