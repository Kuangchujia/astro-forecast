## 五、两项「可选项」的执行结果（2026-09-23 04:45 实测）

### ① `robots.txt` 那两行 —— **删不掉，且不必删**

**现状原文**（`curl` 逐字节取证）：

```
Sitemap: https://kuangchujia.com/sitemap.xml          ← 404
Sitemap: https://kuangchujia.com/news-sitemap.xml     ← 404
User-agent: *
Disallow: /wp-admin/
Allow: /wp-admin/admin-ajax.php

Sitemap: https://kuangchujia.com/sitemap_index.xml     ← 200 ✅
```

**判定（分「原文」与「推论」）**：

* 【原文／实测】**末尾那行**（`sitemap_index.xml`）**在 `User-agent` 块之后** ——
  WordPress 内核 `do_robots()` 的输出顺序是「先 `User-agent` 块、后 `Sitemap` 行」，
  插件的 `robots_txt` 过滤器也是**追加** ⇒ **位置一致，判为 Rank Math 追加**，受插件管辖。
* 【推论，非原文】**前两行**排在 `User-agent: *` **之前** ⇒ **不是**内核与插件的追加位，
  只能是**更上游**写入的。结合 2026-09-21 的实测记录（当时 **Jetpack 那套**
  `sitemap.xml`／`sitemap-1.xml`／`image-sitemap-1.xml`／`news-sitemap.xml` **全 200**，
  而 Rank Math 那套全 404 —— 现在正好**反过来**）⇒ **推定为 WordPress.com 平台／Jetpack 侧写入**。
  **⚠ 本机无法验证写入方**：`robots.txt` 不暴露在 REST 里。
* 【推论，非原文】**个人版没有 robots.txt 编辑权**（wp.com 的 robots 编辑属 **Business 及以上**）。
  **⚠ 同样无法在本机验证** —— **请以后台是否出现 robots 编辑入口为准**（`设置 → 阅读` 或
  `工具 → 营销`／wp.com 的 `设置 → 常规 → 站点可见性` 一带）。★ 只有一点是确定的：
  **Rank Math 的 robots 编辑器只能「追加」，盖不掉前面的行。**

**结论与建议**：
* **不影响收录** —— 主索引已 200 并覆盖全站；Google 只会把这两条记成「无法读取」的噪音提示。
* 想让它们**变成有效声明**：打开 Jetpack 的 sitemap
  （`/wp-admin/admin.php?page=jetpack#/settings` → 性能／流量 → **Sitemap**）。
  但**没有必要** —— 会多出一套口径，与 Rank Math 重复，收益为零。
* ⇒ **建议：无视这两行**。（此项**已判定为「不可执行／不必执行」**，不再列为待办。）

### ② `A` 项（插件版本号）—— **做不了，且不影响成果**

* 本机凭据件 `~/.workbuddy/wordpress-app-password.txt` 是 **19 字符（4 组 ×4）**，
  形态是有效的应用密码，但对站点 REST **一律 401**；`kuangchujia`／`chirc`／`xuzhu`／`admin`
  **四个候选用户名全试过**，均 **401**。
* 与库中记载一致：**用户已自行撤消该密码**（原话「**密码已撤消**」）⇒ **不存在可用凭据**。
* ⇒ **A 项保持「跳过」，这是如实状态，不是缺陷。**
* ⚠ **它对「成果」没有任何影响**：v1.3.0 是否在线上运行，已由**三条独立行为特征**证实
  （事件页出 `Event` 且字段逐字来自本插件数据与源码；站点级实体同时回来 ⇒ 回调优先级 <10 生效；
  坏 `Dataset` 全消而好 `Dataset` 仍在）。**版本号只是 1 个数，验不验都一样。**
* 若要它转绿：`/wp-admin/profile.php` 底部 →「应用程序密码」→ 新建一个 → 跑
  `KCJ_WP_USER=kuangchujia KCJ_WP_APP_PASSWORD='xxxx xxxx xxxx xxxx' python live_verify.py`。
  **纯可选，不做也完全不影响收录与展示。**
